02 Implemented contract

A chain that schedules, branches and adapts

The scheduler evaluates 88 automatic stage declarations against current evidence. Independent branches advance when their inputs are ready; loops revisit useful frontiers as observations change. The Executive maintains the wider view while ACP supplies missing capabilities and AEP repairs the underlying software.

Who decides what happens next?

Each role has a distinct responsibility: scheduling, supervision, bounded interpretation, capability generation or platform repair. Their shared records let the investigation progress beyond one prompt or one tool.

04 Design philosophy

70% deterministic. 30% neural.

RedShades uses this ratio as a design philosophy: dependable software surrounds the places where model judgment adds value. Scheduling, state, policy and validation provide structure; models interpret ambiguity, develop candidates and guide complex engineering work.

How AI allocation connects to product value

The ratio is a design framing, not a measured code, runtime or success percentage. The intended economic advantage is selective intelligence: compact specialists for bounded decisions, persistent sessions for work that benefits from continuity.

10 Implemented contract

Small calls with complete jobs

Bounded stateless AI calls receive a defined purpose and a structured evidence packet. Deterministic code checks the response, attributes the model and retains the accepted result. This is the intended home for compact, fine-tuned specialist models.

What surrounds a decision?

Token accounting, capacity controls and response validation surround the call. A 1B-class specialist is a deployment objective for suitable bounded tasks; the catalog does not claim a trained model bank or measured equivalence to a larger model.

What is the Executive watching?

12 Implemented model boundaries

Compact models, durable engineering context

Persistent Executive, ACP and AEP sessions can use more capable compact models for synthesis and repair. Custom context management carries accepted artifacts, prior review and progress records between segments, so the task does not depend on an indefinitely growing conversation.

How could a compact model contribute?

Model selection is configurable. Terra-low is a documented operating policy in the project history; alternative model deployments require their own evaluation. The architecture targets strong outcomes from efficient models without asserting an unmeasured quality or speed equivalence.

ACP builds evidence-bound capabilities

The Adaptive Capability Pipeline develops custom capability candidates from observed evidence and source mechanics. A persistent workspace owns binding, SDK selection or extension, adapter generation, review and replica validation.

Why persist a generation session?

Compatible catalog artifacts and SDKs can skip generation segments. New work retains its contract and review history, connecting flexibility with reusable, reviewed artifacts.

From an advisory to a reviewed candidate

ACP connects source findings and advisories with typed capability contracts, SDK extensions and reviewed adapters. Where a ready-made proof of concept is absent, the workbench can retain a candidate for controlled evaluation.

What crosses the generation boundary?

Candidate source, metadata and tests are published as a digest-bound set. Admission and isolated review establish the boundary between generated material and an approved artifact.

15 Implemented contract

Review is built into capability production

An isolated reviewer evaluates the candidate against its contract and provenance. Counterfactuals test whether changed names, ordering and evidence still support the same capability, helping turn a one-off result into a reusable component.

Why isolate the contamination reviewer?

The reviewer uses a read-only packet and returns a typed verdict to admission. Generation, review and execution authority remain separately owned.

16 Implemented contract

AEP repairs software while the run is in flight

The Autonomic Engineering Plane owns diagnosis, a persistent repair session, scoped source changes, tests, build admission, hot replacement and verified hand-back. It addresses defects in the platform machinery while ACP addresses missing target interactions.

Where ACP ends and AEP begins

The full repair transaction preserves the run’s context through a provider replacement. Its acceptance is defined by validated hand-back, connecting software engineering work to continued execution.

What is proposed for model allocation?

18 Implemented contract

Hot replacement with continuity

The Runtime Composition Kernel publishes versioned providers and controls leases, rollback and cleanup. New work can adopt a replacement while existing work retains its implementation and engagement records.

What does the composition kernel own?

This is the runtime foundation beneath AEP hand-back. State remains outside replaceable behavior, giving repair a defined boundary rather than requiring a whole-workspace restart.

19 Implemented contract

Workers return results under a lease

Isolated stage workers receive immutable execution envelopes. Results are accepted only against the current artifact, input and generation lease. That prevents an old worker from publishing a plausible result after its authority has expired.

How is stale work rejected?

In-process handlers and isolated workers have different replacement boundaries. The catalog describes the common principle without implying that every component can be replaced at any arbitrary instruction.

Disclosures become a reusable methodology vocabulary

The Trigger Methodology Graph study organized 200 public disclosures into 37 recurring families. In a 40-disclosure identity-disjoint holdout, 39 belonged to a family represented in that vocabulary.

What did the disclosure study measure?

This is family coverage in a curated study, not a count of executed discoveries. It motivates evidence-bound hypotheses and controlled follow-up through the diagnostic graph.

36 Implemented contract

A hypothesis should reveal its missing evidence

Trigger Methodology Graph (TMG) produces evidence-bound diagnostic hypotheses. Shadow Capability Graph (SCG) reasons about missing prerequisites from an immutable snapshot. Bounty Hunting Gates (BHG) retain policy review for proposed hypotheses.

How do TMG and SCG contribute?

Their useful role is to make uncertainty and the next required evidence explicit. A diagnostic graph does not become scheduling or execution authority simply because its suggestion is plausible.
